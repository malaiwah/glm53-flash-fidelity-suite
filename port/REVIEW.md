## Summary

The architecture draft and parity harness are structurally sound: all checkpoint tensor names verified against the BF16 index, KDA safe-gate / DSA kpool-indexer / noaux_tc router / mHC math all cross-check against vLLM and MLX references, and every framework signature the draft touches (TransformerBlock hc wiring, HyperConnection, BlockSparseMLP "dots", MLAttention, GDN conventions, CacheLayer_MLA_fp16, FakeSTC) matches exllamav3 v1.4.4. ================ FINDINGS (ranked) ================

BLOCKER 1 — check_compat's fla floor is provably too low and can pass silently with WRONG math (draft lines 438–463).
fla 0.4.0 introduced KDA (fla-org PR #621, Oct 2025) WITHOUT the bounded SAFE gate; safe_gate/lower_bound landed in a later release. The draft's `min_fla = (0, 4, 0)` therefore accepts installs whose kda kernels only implement `-exp(A)*softplus(g+bias)`. Worse than a crash: upstream signatures end in `**kwargs` (verified live: `def chunk_kda(q, k, v, g, beta, scale=None, initial_state=None, output_final_state=False, use_qk_l2norm_in_kernel=False, use_gate_in_kernel=False, use_beta_sigmoid_in_kernel=False, allow_neg_eigval=False, safe_gate=False, lower_bound=None, ..., **kwargs)` and `def fused_recurrent_kda(..., use_gate_in_kernel=False, use_beta_sigmoid_in_kernel=False, lower_bound=None, ..., **kwargs)`), so on an older fla whose entry points already had `**kwargs`, passing `safe_gate=True, lower_bound=-5.0` may be swallowed and the model runs with the WRONG (unbounded softplus) decay — silent garbage, not an error. Exact fix: replace the version-tuple compare with a feature probe in check_compat:
  `import inspect; from fla.ops.kda import chunk_kda, fused_recurrent_kda`
  `assert "safe_gate" in inspect.signature(chunk_kda).parameters and "lower_bound" in inspect.signature(fused_recurrent_kda).parameters and "use_gate_in_kernel" in inspect.signature(fused_recurrent_kda).parameters`, raising with the install hint otherwise. Note also the vendored vLLM copy uses DIFFERENT kwarg names (compute_gate/a_log/g_bias/sigmoid_beta) than upstream (use_gate_in_kernel/A_log/dt_bias/use_beta_sigmoid_in_kernel) — item B must be written against the UPSTREAM names; the local refs/kda.py is the vLLM vendored variant and is a trap here.
Related minor: the tuple compare itself misfires on 2-component versions ("0.4" → (0,4) < (0,4,0) → spurious failure); moot once the probe replaces it.

All declared; nothing else in the draft blocks instantiation once they land — every other constructor call was signature-checked against v1.4.4 and is exact (TransformerBlock attn_hc/mlp_hc, HyperConnection(hc_mult/hidden_size/sinkhorn_iters/hc_eps/rms_norm_eps), BlockSparseMLP(router_type="dots", act_limit, n_group/topk_group, key_e_score_bias), GatedMLP(activation_fn, act_limit, select_hq_bits), Linear(caps/qbits_key/alt_key), Embedding, RMSNorm, prepare_for_attn + prepare_for_recurrence(input_ids, params, self) per qwen3_next).
(c) One spec item for C the harness will police: kpool selection is POOL-granular — `select_k = min(index_topk // index_kpool, P)` complete visible pools (pool_end <= q_pos) + always-select-tail of `(i+1) % kpool` raw tokens (verified identically in vLLM attention.py/kpool_compress.py and mlx_language.py lines 261–437). The current `_indexer_topk` counts TOKENS (`k_sel = min(index_topk, t_slab)`); porting it unchanged under kpool would select 4x too few pools and the harness sparse test will (correctly) fail.

MAJOR 3 — the harness's central mHC claim is false: nothing "fails loudly" without the allow_bf16 patch.
loader/safetensors.py get_tensor silently converts when the flag is absent: `bf16_to_fp16 = (dtype == torch.bfloat16 and not allow_bf16)` — no exception. So HyperConnection.load() on the GLM checkpoint succeeds today, and the hc parity rows would PASS within tolerance, giving false assurance that the patch landed. The conversion is exact only for bf16 values in fp16 normal range; hc_attn_fn entries below 6.1e-5 (plausible at the observed ~1e-4..1e-2 scale) become fp16 subnormals and quietly lose mantissa bits — precisely the fidelity leak the patch exists to close. Exact fix in exl3_run_hc(): after `hc.load(device)`, add
  `ref_fn = R.get(f"{hc_key}_fn", device).float(); assert torch.equal(hc.fn, ref_fn), "hyperconnections.py is missing the allow_bf16 load patch (fp16-rounded hc tensors)"`
(ditto _base/_scale). torch.equal is the right test: bit-exact iff the module loaded true bf16. Keep the skip message, but now it can actually trigger.

MAJOR 4 — MoE parity rows can FAIL on legitimate router tie flips; add a same-selection control row.
exl3 "dots" routing runs the CUDA top-k on fp16 logits with a mean-centered fp16 selection bias (block_sparse_mlp.py `_esb_h`, `ext.routing_ds3_nogroup(..., ROUTING_ACT_SIGMOID)`), while the reference (and config: moe_router_dtype "float32") routes in fp32. With 288 experts × 64 tokens, near-tie expert flips are expected on real weights; a single flipped 8th expert can push one token past tol_rel=5e-2 and the run reports FAIL with no way to distinguish "math bug" from "tie flip". The tie-margin diagnostic helps interpret but doesn't gate. Exact fix: read back exl3's selected expert sets (or recompute selection with fp16-quantized biased scores in the reference), report (a) top-8 set agreement rate and (b) a reference output computed WITH exl3's selection — gate PASS/FAIL on row (b), keep the free-selection row as informational.

MINOR 5 — ContractStreams should emit fp32, not fp16 (draft comment says "fp16 out"). vLLM contracts then norms in bf16; dsv4's HyperHead hands fp32 to the final RMSNorm(out_dtype=half). Mean the 4 fp32 streams and return fp32; the norm does the cast. Free precision, zero cost.

MINOR 6 — o_norm epsilon is a lucky coincidence, document it. vLLM constructs `FusedRMSNormGated(head_dim, activation="sigmoid")` with the FLA default eps=1e-5 (verified upstream: `eps: float = 1e-5`), which happens to equal rms_norm_eps. The draft passes config.rms_norm_eps — correct today; add a comment (or assert rms_norm_eps == 1e-5 near the KDA construction) so a future config change doesn't silently diverge from the reference's hardcoded default.

MINOR 7 — draft comment arithmetic on the clamp deviation: the ≤4.5e-4 bound is per unit of up-value; with |u| clamped to 10 the output deviation bound is 4.5e-3 (still far below bf16 resolution at that magnitude — conclusion stands, wording overstates). Verified both conventions precisely: vLLM SiluAndMulWithClamp = `clamp(g, max=limit) * sigmoid(g_clamped) * clamp(u, ±limit)` (refs/vllm_activation.py forward_native), exl3 activation_kernels.cuh = silu then `x2 = __hmin2(x2, limit)`, `y2` clamped ±limit. Deviation only for g > 10. Accepted-as-is is the right call.

MINOR 8 — harness kernel-path claims are unverifiable from outside the module: "T=32 exercises the fused recurrent path / T>=--seq the chunk path" depends on item B's internal dispatch (GDN's stateless path may route both through the chunk kernel). Either add an introspection counter the module increments per kernel, or soften the claim; otherwise two rows may test one path.

MINOR 9 — exl3_run_dsa_cached leaks the cache layer on exception (layer.free() not in a finally). Cosmetic; the process exits anyway.

MINOR 10 — draft passes index_kpool to "shared"-mode MLAttention layers too (meaningless there, harmless; GLM-5.3 ships all-"full").
